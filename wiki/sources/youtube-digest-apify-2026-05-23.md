### #3 Simon Scrapes — *Build Self-Improving Claude Code Skills. The Results Are Crazy.*

**109.7K views, 2026-03-13, 11:02. → New concept: [[self-improving-skills]]. Updates [[simon-scrapes]], [[skill-creator]], [[karpathy-llm-wiki]], [[claude-code]].**

The **highest-views video of the batch and Simon's vault entry-point #2** (his prior 30.5K-view Skill Systems video was the framework definition; this is the *evals-loop* extension). Core claim: take inspiration from [[andrej-karpathy]]'s `autoresearch` concept and apply it to Claude Code skills — set up an **autonomous overnight loop** that tests, scores, and refines skills based on **binary criteria**, ensuring skills get more reliable with every iteration.

**The framing claim**: *"What if your Claude Code skills could improve themselves overnight while you sleep?"*

**The Karpathy lineage** (referenced explicitly):
- **`karpathy/autoresearch`** — the parallel-tracked artifact previously surfaced via [[dubibubii]]'s 33-tool curation (2026-05-05) and now confirmed as [[andrej-karpathy]]-authored after his 2026-05-19 Anthropic hire
- Simon's pattern is the **skill-tier instantiation** of autoresearch — autoresearch was open-ended research-agent; self-improving skills is **bounded skill-tier improvement** with explicit binary scoring

**The autonomous loop** (the framework):

```
1. Run skill against test inputs
2. Score against binary criteria (pass/fail per criterion)
3. If failures: generate skill revision
4. Run revised skill against same tests
5. Compare scores
6. Keep revision if improved, discard if worse
7. Repeat (overnight, sleeping)
```

**Binary criteria are the unlock** — pass/fail bypasses subjective quality judgments. The criterion list becomes the skill's contract. Same shape as [[skill-creator]]'s plain-language evals but with **closed-loop optimization** (Skill Creator runs one eval; self-improving runs until convergence).

**Where it fits in the [[claude-skills]] eval stack**:

| Tool | Loop shape | Time horizon |
|---|---|---|
| Hand authoring | Manual eval, manual revision | Minutes per cycle |
| [[skill-creator]] | Single-shot A/B eval | One run |
| **[[self-improving-skills]]** | **Autonomous loop with binary criteria** | **Overnight — N iterations** |
| Future (predicted) | Skill marketplace with auto-improvement | Continuous |

**The closed-loop architecture** — explicit positioning beyond Skill Creator's single-shot A/B:

- [[skill-creator]] tells you *whether* the skill works (one run)
- [[self-improving-skills]] makes the skill *converge* on working (N runs, autonomous)
- Together: the **author → optimize → ship** pipeline gets fully automated

**Strategic significance**:

### #4 Nate B Jones — *The One AI Writing Hack Nobody Talks About.*

**22.3K views, 2026-05-22, 21:50. → New concept: [[project-room-workflow]]. Updates [[nate-b-jones]] (17th framework), [[ai-question-method]], [[claude-code]].**

The unlock event: **prestigious law firms (Sullivan & Cromwell) filed federal-court motions full of AI hallucinations**, despite using frontier models. The common story is "better prompts prevent hallucinations" — the reality is more complicated. The fix is **shaping the canvas before the writing starts**.

**Chapter map**:

**The framing claim**: *"What's really happening when prestigious law firms file motions full of AI hallucinations? The common story is that better prompts prevent hallucinations — but the reality is that operators doing high-stakes knowledge work with AI agents need to shape the canvas before the writing starts, or they ship the same soft spots that landed Sullivan and Cromwell in front of a federal judge."*

**Why better prompts cannot fix this** (chapter 1:30) — the canonical critique. Prompt engineering operates inside the agent's available context. If the available context is **messy source material with duplicates, conflicts, and gaps**, no prompt can fix the source. Hallucinations aren't a model failure; they're a **canvas-shape failure upstream of the prompt**.

**What changed with Opus 4.7 and GPT-5.5** (chapter 3:00) — the 2026-Q2 model capability jump means **agents now walk folder trees and compare files cleanly**. Pre-4.7, you had to feed the model curated chunks. Post-4.7, the agent can navigate a project structure on its own — *if you give it a project structure to navigate*. The new substrate enables the workflow.

**Three takeaways for serious knowledge work** (chapter 4:30) — diagnostic framing:
1. Your first AI prompt should never be "do the thing"
2. Agents now walk folder trees and compare files cleanly (post-4.7 capability)
3. Artifacts make an agent's judgment visible and inspectable

**Why your first prompt is never "do the thing"** (chapter 6:00) — the **canvas-shaping discipline**. The first prompt builds the canvas; the second prompt does the thing. Most operators skip step 1 and ship the soft spots.

**The Project Room Workflow** (chapter 9:00) — the **three canvas artifacts** as first-prompt outputs:

| Artifact | Built when | What it does |
|---|---|---|
| **Source inventory table** | First prompt | Lists every source — name / path / type / date / authoritativeness — so the agent (and the reviewer) can see what's in scope |
| **Conflict log** | After source inventory | Surfaces explicit contradictions across sources — what page X says vs what page Y says, with citations to both |
| **Missing context list** | After conflict log | Names what *should* be in scope but isn't — gaps the agent can't fill without explicit instruction |

The three artifacts are **the canvas**. Only after they exist does the writing prompt go in. The writing prompt itself becomes **short** (chapter 20:00) because the canvas does the heavy lifting.

**Where to build your room across tools** (chapter 10:30) — implementation specifics (gated to transcript). Pattern fits Claude Code (CLAUDE.md + raw/ folder), Cursor (`.cursor/` + workspace), or ChatGPT Projects (uploaded files). The artifacts are tool-independent.

**Why duplicates are a reasoning problem** (chapter 17:00) — the deep claim. Duplicate sources don't just waste tokens; they **break the agent's reasoning** because the agent sees the same claim twice and treats it as two independent confirmations. The conflict log + dedup discipline is **information-quality infrastructure**, not just hygiene.

**Files as the canvas for agentic work** (chapter 18:30) — the substrate claim. **The filesystem is the canvas**, not the prompt window. Files persist across agent runs, can be inspected by humans, and form the unit of revision. Same shape as this vault's `raw/` → `wiki/` architecture.
